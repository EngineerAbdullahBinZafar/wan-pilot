# Pull Request: Prevent Silent Video Save Failures with Codec Cascade & Frame Dump (Fixes #416)

## Description
When hardware NVENC encoders fail (e.g., driver version mismatch or containerized headless runners lacking CUDA codec binaries), the video saving routine in `wan/utils/video.py` silently swallowed the exception or left an empty 0-byte `.mp4` file while returning exit code 0. Users spent 10+ minutes rendering latents only to find no video file was created.

## Changes
- Implemented a robust multi-tier fallback cascade: `h264_nvenc` $\to$ `libx264` $\to$ `libopenh264` $\to$ `mpeg4`.
- Added post-write file verification: verifies that the target `.mp4` exists and has byte size $> 1024$ bytes.
- Added disaster frame dumping: if all video encoders fail, raw PNG frames are dumped to disk, preventing irreversible loss of compute tokens.

## Testing & Verification
- Unit and adversarial tests verify automatic cascade progression when hardware NVENC raises subprocess return codes != 0.
